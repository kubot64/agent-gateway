# 書き込みは全件承認し、承認できるのは依頼者本人だけにする

書き込みはすべて、実行前に依頼者本人の承認を必要とする。影響が依頼者自身にしか及ばない自分宛てのリマインドも例外にしない。例外を作ると「全書き込みに承認が適用されている」と言えなくなり、何が自分宛てかを判定するロジックがそれ自体新しい攻撃面になるからだ。承認できるのは、プラットフォーム・ワークスペース・ユーザー ID の 3 つ組が依頼者と一致する人だけである。承認の対象は、ボットが解釈した意図ではなく、dry_run で示した実行内容とする。承認待ちは 24 時間で期限切れになり、期限切れの書き込みは実行しない。期限切れはボタンが押された時点で判定して知らせる。時刻で動く仕組みを持たないためだ。

書き込みかどうかはツール自身の宣言だけで決め、意図や文中の文字列では判断しない。承認待ちは DB に保存し、承認済みへの遷移は 1 回に限る。承認後は、承認時に保存した実行内容をそのまま実行する。ツールを登録簿から取り出して実行する経路は policy 層だけが持ち、app 層からツールを直接実行できない形にする。

## Consequences

- Discord には承認の UI がないので、Discord からは読み取りだけを受け付け、書き込みは Slack に誘導する。
- 署名検証なしで承認できた `/api/agent/confirm-action` は廃止する。承認は署名検証済みの Slack interaction からだけ受け付ける。
- 登録されたすべての書き込みツールについて、承認なしでは実行されないことを 1 本のテストで確かめる。ツールを足すとテストの対象も自動で広がる。

## Considered Options

- **自分宛ての書き込みは承認を省く**: 毎回 1 クリック減るが、上の理由で却下した。
- **ワークスペース管理者も承認できる**: 依頼者が不在でも進められるが、「本人のみ」の不変条件が崩れるので却下した。
