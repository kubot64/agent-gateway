# agent-gateway 計画（2026-11-05 合意）

秘書ボットを「エージェントを安全に Slack / Discord へ繋ぐための基盤」として再定義し、
`home` から独立リポジトリ `agent-gateway` に切り出す。判定日は 2027-02 上旬。

## 目的と読み手
- ポートフォリオ優先。ただし自分が毎日使う（docs.search）。
- 読み手は採用側のシニアエンジニア。副として技術記事の読者。
- 文書は日本語。README 冒頭に英語 3 行要約のみ。

## 「安全」の定義（4 つ）
1. 入口: 署名検証、リプレイ防止、冪等性（実装済み）
2. 操作: 書き込みは全件承認、読み取りは承認なし、承認は依頼者本人のみ
3. 供給: フォールバック、degraded 明示、コスト上限
4. インジェクション分離: instruction / data の分離、data 由来の内容からツールは発火しない

対象外: ローカル LLM によるデータの安全。

## 形
- `agent-gateway` を `git subtree split` で履歴ごと切り出し、初日から public。公開前に gitleaks で履歴を走査。
- ディレクトリは gateway / policy / tools / app の 4 層。ライブラリ化はしない。
- main 直接 push 禁止。全部 PR。本文は「背景・変更・検証方法」。
- CI に ruff と mypy を追加。Python >= 3.11。
- Slack を主、Discord は維持のみ。

## 操作の安全
- Tool Executor 共通 I/F: name, input_schema, execute, idempotency_key, dry_run。
- リマインド、Linear、設定変更をすべて Tool Executor 経由にする。
- 承認待ちは DB に永続化（Cloud Run のインスタンス入れ替えに耐える）。
- 意図分類はルールベースのまま固定し、ADR で安全境界として説明。

## インジェクション分離
- LLM 入口を役割付きメッセージ列に変更。
- 呼び出しユーザーの指示 = instruction、スレッド発言・検索スニペット = 区切られた data。
- CI は偽 LLM で構造検証（`tests/injection/`、10〜20 件）。
- 本物の LLM への評価は手動で回し、成功率と失敗パターンを `docs/reports/` に日付付きで残す。

## 供給の安全
- 主: OpenAI gpt-4o-mini（前払い 5 ドル）。副: Gemini 無料枠。両方落ちたら degraded ステータスで固定文。
- max_tokens、リトライ 1 回、ユーザー別・日別トークン上限（既定 100,000、環境変数）。
- 主→副→degraded の 3 段階を模擬した試験記録を残す。
- キーは Secret Manager のみ。リポジトリには入れない。

## 毎日使う機能
- docs.search。文書は私用 GCS バケットに `make sync-docs` で同期し、起動時にインデックス構築。

## 文書
- ADR 5 件（`docs/adr/`、形式は文脈・決定・却下案・結果、1 件 1 ページ）
  1. 冪等性を API 側だけで持つ（既存文書を移す）
  2. 意図分類をルールベースに固定する
  3. 書き込み操作は全件承認・本人のみ承認
  4. instruction / data 分離とツール発火の不変条件
  5. フォールバックは明示的に degraded を返す
- README の順: 英語要約、解決する問題、構成図、4 つの安全とコードリンク、テスト集リンク、動かし方、ADR 一覧、試験記録リンク。
- 技術記事はインジェクション分離が主題。Cloud Run 構築の既存下書きは導入編として先行公開可。

## 2026-11-05 時点の実装状況（調査結果）
- 承認が必要なのは `/remind` に「all」「全員」を含む場合のみ。Linear・自然文リマインド・設定変更は承認なし。
- 承認後処理はリマインド作成にハードコード。承認者の本人確認なし。承認待ちはプロセス内メモリ。
- system プロンプトは固定 1 文。要約時は他ユーザー発言 30 件を生のまま連結。区切りなし。
- プロバイダは OpenAI と固定文ローカルのみ。障害時は無通知で固定文、ステータスは completed のまま。リトライ・max_tokens・コスト上限なし。
- CI あり（unittest 42 件、Postgres/Redis E2E）。lint・型チェックなし。
